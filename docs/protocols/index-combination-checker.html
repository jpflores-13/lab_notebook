TruSeq Nano Set A color-balance validator for pooled sequencing indices

Published

September 9, 2026

NoteOverview

This is a standalone reactive tool, not a bench protocol — it checks whether a chosen set of TruSeq Nano Set A indices is safe to pool on an Illumina run. Illumina’s sequencer base-calling relies on seeing a mix of red/green (or, on two-channel instruments, distinguishable) signal at every cycle; if every pooled index shares the same base at a given position within the index read, that position has no color diversity and can fail to call correctly. The rule (from Illumina’s Index Adapters Pooling Guide): at each of the 6 index positions, the pooled set must contain at least one index with an A or C at that position and at least one index with a T or G. This tool reproduces that logic (the source spreadsheet’s COUNTIF-based validation) for any set of indices you select below.

ImportantBefore starting
  • This checks color balance only — it does not check for index sequence collisions, i5/i7 pairing, or demultiplexing edit-distance requirements. Cross-check those separately.
  • Reproduced from Index_Combinations.xlsx, TruSeq Nano Set A lookup (12 indices).

Inputs.table(all_indices, {layout: "auto"})

Choose indices to pool

Code 
viewof chosen_indices = Inputs.checkbox(all_indices, {label: "Chosen indices", format: d => `${d.name} — ${d.seq}`, value: [all_indices[0], all_indices[1], all_indices[2], all_indices[3], all_indices[4], all_indices[5], all_indices[6], all_indices[7]]})
Code 
positions = [0, 1, 2, 3, 4, 5]

color_check = positions.map(i => {
  const bases = chosen_indices.map(idx => idx.seq[i]);
  const hasAC = bases.some(b => b === "A" || b === "C");
  const hasTG = bases.some(b => b === "T" || b === "G");
  return { position: i + 1, bases: bases.join(""), hasAC, hasTG, ok: hasAC && hasTG };
})

all_ok = chosen_indices.length >= 2 && color_check.every(r => r.ok)
Code 
chosen_indices.length < 2
  ? md`::: {.callout-tip}
Select at least 2 indices to check color balance.
:::`
  : all_ok
    ? md`::: {.callout-note}
## ✅ Good combination!
${chosen_indices.map(d => d.name).join(", ")} — all 6 index positions have color diversity (at least one A/C and one T/G at every position).
:::`
    : md`::: {.callout-warning}
## 🛑 BAD COMBINATION!!!
${chosen_indices.map(d => d.name).join(", ")} — the following position(s) fail color balance: ${color_check.filter(r => !r.ok).map(r => `**position ${r.position}** (needs ${!r.hasAC ? "A/C" : "T/G"}; bases seen: ${r.bases})`).join("; ")}. Swap in a different index to fix these positions.
:::`

Per-position base composition

Code 
Inputs.table(
  color_check.map(r => ({
    Position: r.position,
    "Bases at this position (chosen indices, in order)": r.bases,
    "Has A/C?": r.hasAC ? "✓" : "✗",
    "Has T/G?": r.hasTG ? "✓" : "✗",
    "Balanced?": r.ok ? "✓" : "✗"
  })),
  {layout: "auto"}
)
TipImprovement over the source spreadsheet

Index_Combinations.xlsx validated only the first 8 pasted rows (its COUNTIF ranges were hardcoded to G5:G12) — a 9th or later pasted index was silently ignored by the “VERDICT” formula even though it appeared in the “chosen indices” list. This tool checks every index you select, with no fixed row cap.
